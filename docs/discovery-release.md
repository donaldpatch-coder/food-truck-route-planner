# Lowell discovery release — November 16, 2026

Implements the supplied hero, live feed, split map and For Businesses wireframes using the existing static site and CSS. The original owner app and its PWA remain intact. No Tailwind build dependency, new hosting project or paid maps/search subscription was added.

## Source-backed launch listings

`data/lowell-launch.json` records 36 public-source listings: 34 Lowell storefront addresses plus two traveling trucks serving the region. Each has a source URL and source-check date. Sources include business websites, Lowell's official bakery guide, Lowell Summer Music Series, the Whistler House visitor guide and regional tourism sources. Address positions and postal codes are from the US Census geocoder; these are approximate street positions. Regional trucks have no invented ZIP, current stop or map pin.

These are unclaimed public-source records, not verified operating businesses or confirmed open-now schedules. No external reviews, star ratings, view counts, opening hours, prices or live statuses were imported. Source records may become outdated. Rechecking a source is not independent confirmation that an establishment remains open.

Source keys support idempotent imports without overwriting owners. IDs were generated by Postgres; import left user_id null. Existing accounts, reviews and owner records are retained. Before adding more sources, verify names/addresses and preserve provenance; do not scrape review text or imply a business endorsement.

## Claim requests and manual review

Signed-in non-anonymous users can request a claim on an unclaimed published listing. Requests are visible only to their requester through the public API; the service/database operator can inspect the private review queue in `streetbite_claim_requests`. A requester cannot set approval status, take ownership or edit an imported listing. No claim notifications or outreach messages are sent automatically.

Before assigning ownership, independently verify the requester through an existing public business contact channel. Do not accept a newly supplied email address alone as proof, and do not request passwords or identity documents. A privileged operator should update the existing listing user_id and mark the corresponding pending request approved in one transaction after verification, confirming that the listing is still unclaimed and retaining its ID/source key. Decline conflicting claims after review. Public clients have no permission to perform this transition.

## Live check-ins

An account-owned business can post a public service address, short stop note, optional business photo URL and duration from 30 minutes to four hours in My Listings. The address is geocoded against the Census service. Live coordinates are separate from the base listing, so expiry restores the base map position. The owner can end the stop early. A database trigger enforces owner presence, location and maximum duration. Client time is not authoritative for public filtering: the discovery RPC uses database now().

The feed and map label these as owner check-ins, not independently verified GPS or opening-hours claims. There is no background location tracking. The homepage refreshes while visible once per minute; expired cards can remain visible until that refresh. No staged check-ins are left in production.

## Search, maps and reviews

ZIP/city lookups use Zippopotam.us / GeoNames, with US state default MA for city-only queries. Location permission is requested only after the visitor presses Use My Location. Coordinates are kept in page memory, not saved as a location history. Distances are straight-line miles with 5/10/25-mile filters. Regional mobile records without a location are separately labelled and never pinned.

The split map uses pinned Leaflet 1.9.4 and standard OpenStreetMap tiles, visible attribution, normal browser caching and no bulk/offline tile caching. External providers are best-effort services, not a guaranteed paid maps SLA. API requests and map tiles are not put into the PWA cache. Saved spots are browser-local and labelled as saved on this device. Community cards use only actual Street Bite reviews; empty states do not fabricate testimonials.

Six local guide pages, sitemap and robots.txt are generated with `python scripts/build-local-guides.py`. They contain indexable public-source records rather than search-only JavaScript, and link back to current directory/claim details. No unsupported "best" rankings or review schema are published. Regenerate after reviewed data updates.

## Validation

Database transaction tests passed public discovery, private claim visibility, blocked self-approval and unclaimed edits, reviews on unclaimed listings, self-review denial, live check-in appearance, expired check-in removal and maximum duration. All test users, claims, reviews and listings were rolled back. Location endpoint tests passed ZIP, city, public address and unsupported-method checks. Browser checks covered radius/category discovery, synchronized map pins, saved-spot filtering, listing details/claim links and mobile header/search sizing. Device GPS permission and a real owner's sign-in/check-in were not exercised on the user's behalf.

Monetization proposals remain planning only: no checkout, paid tier, automatic booking/lead fee or featured placement was activated. Live automatic social posting still requires the existing provider configuration.
